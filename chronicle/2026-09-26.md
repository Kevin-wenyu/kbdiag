### 改动

- `internal/facts/inst.go`：`inst.info` 加 `port`、`usable_connections`（列追加在末尾，老列顺序不变），`version` 改成短版本号；`inst.downstreams` 改成每个 walsender 一行（`application_name`、`client_addr`、`state`、`sync_state`）；新增 `inst.upstream`（`status`、`sender_host`、`sender_port`、`slot_name`、`last_msg_age_s`）和 `inst.disk`（`total_bytes`、`used_bytes`、`avail_bytes`）；downstreams 的 `state`/`sync_state` 和 upstream 的 `status` 为 NULL 时记 `redacted[]`
- `internal/probe/inst.go`：新 SQL（`host(client_addr)` 去掉 `/32`）；`InstUpstream` 在主库上直接返回 `not_applicable`（reason `primary`）；`InstDisk` 做 statfs，socket 或 loopback 且可 stat 才读，远程 `not_applicable`（reason `remote connection`），`data_directory` 看不到时 `skipped`，socket 下 stat 失败是 `error`；`statfs_{linux,darwin,other}.go`
- `internal/conn/conn.go`：`Config.Loopback()`（localhost、127.0.0.1、::1）
- `internal/rule`：删 `ConnWarnPct`/`ConnFailPct`；`inst.connections` 只在已用 ≥ 可用时 FAIL；新增 `inst.upstream` WARN（没有接收进程 / 状态不是 streaming），next 是 `verify: kbdiag slots`（到主库上跑）；upstream 的 status 被遮蔽时 verdict UNKNOWN；`inst.disk` 不进 rule
- `internal/report/status.go`：status 专用文本排版；`render.go` 把表格输出拆成 `writeTables`
- `cmd/kbdiag/main.go`：删 `--conn-warn`/`--conn-fail`，接上两个新 probe
- 测试：`internal/scenario/testdata/status_{primary,standby,standby_no_walreceiver}.txt.golden` 是**手抄上一节用户确认的草样**，代码输出和它逐字一致；另两个 golden（`status_masked_full`、`status_unknown`）是代码生成后人工看过的。PRD §5.1 新增"status（备库）"示例，两个示例都用 18:28 的实采数据，作为 JSON golden

- **全部 VM 验证都没做**：`KB_TEST_NODE=kes-node1|kes-node2 go test -tags vm ./e2e/...` 要回本地跑。重点看：
  - `split_part(version(), ' ', 2)` 和 kbdiag 的短版本号一致
