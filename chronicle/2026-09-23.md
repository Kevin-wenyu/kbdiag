## 阶段 0.3：注入脚本

`e2e/inject/`：`lib.sh` + 6 个场景（`lock`、`idle_txn`、`long_query`、`prepared`、`track_off`、`slot`），用法 `KB_TEST_NODE=<node> ./<名>.sh up|down`，参数错误 exit 64。在 Mac 上运行，通过 `limactl shell` 驱动 VM；注入的会话都带 `application_name=kbdiag_inj_<tag>`，down 按进程组 + tag 两路清理。up 会一直等到目标状态出现才返回，测试里不用自己 sleep。

手工验证（up → 独立查询 S1~S4 → down → 再查），全部 exit 0：

```
lock        up 1s   holder:AccessExclusiveLock:granted=true | waiter:AccessShareLock:granted=false:blockedby={236153}
            down 1s 表已删除
idle_txn    up 1s   idle in transaction:xid=5855           down 1s → 无
long_query  up 1s   active:select pg_sleep(3600);          down 1s → 无
prepared    up 1s   kbdiag_inj_2pc:system:test             down 0s → 无，表已删除
track_off   up 1s   track_activities=off                   down 1s → on
slot        up 31s  repmgr_slot_2:active=false:xmin=5859   down 1s → active=true
残留        注入会话 0 / sleep 进程 0 / prepared 0；node2 walreceiver streaming；repmgr 两节点 running
```

决策与坑：

- **slot 场景用暂停备库 walreceiver（SIGSTOP）实现**，不停实例、不断网：wal_level=replica 建不了逻辑槽；node2 上 kbha 守护进程加 cron 每分钟会拉起停掉的实例；断网则可能触发 repmgr 故障切换。暂停 walreceiver 后，经过 wal_sender_timeout（30s），槽变成非活跃但保留 xmin，和"备库挂了"的真实形态一致
- **ksql 输出布尔值是 `t`/`f`**，不是 CLAUDE.md "KES 特有行为"里写的 `true`/`false`（那条来自 shell 版，语境不同）；0.4 改写 CLAUDE.md 时要更正
- macOS 自带的 bash 3.2 在 `$(cat <<'EOF' ...)` 里遇到 `case` 模式的 `)` 会解析错；改用前导括号 `(t | true)`
- 第一次跑时 `wait_for` 全部超时，原因是上面的 t/f 比较，另外它按循环次数计时（每次调用 ksql 都有开销，实际等了近 10 分钟）；已改成按 `SECONDS` 计真实时间
